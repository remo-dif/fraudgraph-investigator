# ADR 0002 | Dataset Isolation

Status: proposed implementation direction for Phase 1A.

Logical partitioning in one instance is operationally cheap, but routing mistakes, a broad credential or legacy reads could expose unrelated records. Use one dedicated Neo4j Community instance and volume per private imported-data deployment, separate from the demo instance. Avoid an instance per dataset within a single-customer installation. Within the import instance, enforce logical dataset/version boundaries as defense in depth. Community supports one standard user database per instance; Enterprise database separation and fine-grained privileges are not assumed. Document actual runtime/admin privileges before a pilot. [Neo4j databases](https://neo4j.com/docs/operations-manual/current/database-administration/standard-databases/)

Use mutually exclusive demo and import profiles. Fail closed on ambiguous profile selection or missing import connection configuration. Register demo controllers, fallback security and seed runner only in demo; register imported routes and deny-by-default security only in import. Use different endpoints, networks, credentials and volumes. Demo credentials must fail on the import instance. Pilot ingress exposes HTTPS only, with API and database private.

Use Spring Security to derive a stable actor key from validated issuer and subject (test identities for synthetic CI). Select and document the pilot identity provider before deployment. Never derive actor identity from an upload, request parameter or forwarded header alone. The server assigns ownership at creation. Authorize every operation on dataset and version, return equivalent responses for absent and inaccessible resources, and produce an immutable authorized scope passed to repositories. Check ownership and active state inside mutation transactions. Require both endpoints and the relationship to match dataset/version on writes and reads. Never reuse unscoped demo repositories for imports.

Include principal, dataset, version and request parameters in frontend cache keys. Cancel requests and clear scoped cache on logout, authority changes or deletion, and discard late responses. Delete revokes read/import/export access before cleanup. Separate runtime and schema credentials where the supported edition can enforce it; application policy does not contain a compromised broad database credential.
